# LexFlow 详细使用教程事实核对

核对范围：仓库 `docs/mvp-deployment.md`、`docs/business-rules.md`、`ai-service/README.md`、`.env.lexflow.example`，并结合 `web/src/pages`、侧栏导航、`DocumentService.reviewVersion` 与 `ContractReviewService.request` 二次核对实际行为。未读取或输出真实私密环境文件。外部模型目录若用于操作演示需另行核实。

本教程使用项目真实前端和本地虚构教学数据，AI 结果来自本地教学模拟接口。本次视频制作没有调用真实付费模型，也不构成模型质量、真实向量供应商或生产部署验收。下文提到的历史验收仅是仓库文档记载，应与本教程演示严格区分。

## 建议章节顺序

1. **认识 LexFlow 与准备演示资料**：面向律所的案件、成员、文件解析、文书版本、知识库、AI 起草/审查/案件分析、任务与审计。演示采用合成案件与材料。先学不依赖付费模型的基础闭环，再配置 AI，再进入知识检索与恢复。
2. **安装与首次初始化**：Docker/Compose v2/OpenSSL → 自动生成私密部署配置 → 构建三个应用 → 基础设施就绪 → 工作流建表 → bootstrap 管理员 → 普通启动 → 业务健康及页面验证。
3. **登录与角色**：律所 ID、用户名、密码；管理员、律师、只读成员。律师仍必须是目标案件成员，管理员仍受接口明确权限约束。最后一名有效管理员不能禁用或降级。
4. **案件和团队**：创建案件、设置负责人和成员、进入案件；读取与编辑权限分别讲。归档案件可按权限读取与导出，不能编辑或继续 AI 计算。
5. **上传与解析**：案件文件上传支持 TXT、DOCX、PDF、PNG、JPEG；文字提取仅支持 TXT、DOCX、带文字层 PDF。上传后必须在文件行主动点击“提取文字”，再到侧栏“任务记录”查看状态；成功后点击“查看原文”核对文本。上传不会自动解析，扫描件当前没有 OCR。
6. **人工文书与版本**：编辑、先保存、查看历史、恢复历史成为新人工版本、发布。并发冲突保留本地正文，对照最新内容手动合并后选择“我已对照合并，继续编辑”，仍需再保存。
7. **异步 TXT 导出**：固定已保存版本 → 创建导出任务 → 等成功 → 下载核对。没有保存的修改不会进入文件；后续新版本不改变原导出；AI 待审/驳回版本不能绕过复核导出。
8. **管理员 AI 配置**：用途 LLM/Embedding/Rerank 分开；填服务商、HTTPS 地址、模型、只写 Key；主密钥与模型 Key 各司其职；保存本身无模型调用；连接测试逐次确认费用。
9. **AI 起草与人工复核**：先保存正文 → 填生成要求 → 确认费用 → 提交 → 任务中心查结果及待补信息 → AI 独立待审版本 → 在版本历史点击“通过”即采用为当前正文 → 再按需发布/导出。不会覆盖生成期间人工正文。
10. **合同审查与补材**：选择当前案件可用合同文件，点击“审查合同”（不强制先有解析任务；建议先提取文字核对原文）→ 选择审查立场/关注点、明确的参考库 → 阅读费用提示后点击“提交审查”（初次无独立费用勾选框）→ 查看报告/依据定位 → 高风险/冲突/缺依据/缺材料进入人工复核 → 按需选择 1–5 份补材、续审要求、再次确认费用 → 复核决定。
11. **案件分析**：选同案件 1–10 份已解析材料、输入背景及要求 → 确认费用 → 分清材料事实、推论、待核实、争议、证据缺口、建议和限制 → 原文定位 → 有要求时人工复核。
12. **知识库与资料问答**：管理员创建公共库、上传、主动提取文字、准备入库、主动索引；公共仅指同律所授权成员可读；案件材料不自动进入公共库。需要真实 Embedding 与可选 vector 服务；问答需要 LLM。问题可能扩大一次检索、增加费用；点引用查看真实来源；不足时明确拒答。私人会话连管理员也不能读取同事历史。
13. **任务中心与异常恢复**：侧栏“任务记录”进入“异步任务中心”，排队/执行/成功/失败/取消/人工处理；瞬时基础设施故障有限重试；投递问题从任务行“处理记录”统一恢复；已保存结果复用；不确定付费调用不得直接重发或人工批准绕过，应先核对，取消后主动决定是否新建任务。
14. **审计、日常运行和边界**：从侧栏“文书”进入“操作审计日志”页签；管理员看本律所、普通有权成员看本人审计；用 traceId 帮助定位；ps/logs/health；正常 down 保留具名卷；配置和数据备份、主密钥保留；当前没有内置充值、统一账单或完整生产监控/通知。

## 单机安装准确命令

从仓库根目录执行。宿主机需 Docker Engine/Desktop、Compose v2、OpenSSL；镜像用 JDK 21、Node.js 24，宿主机不另需 Java/Node/Maven。默认入口仅 `127.0.0.1:8088`。基础服务内存上限合计约 3.9 GiB，vector profile 约 6.2 GiB；构建另需空间。

```sh
sh deploy/configure-mvp.sh
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml config --quiet
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml build api
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml build ai-service
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml build web
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml up -d --wait mysql redis rabbitmq minio
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml run --rm workflow-setup
```

生成器只建不存在文件，权限 0600；不覆盖旧配置。`.env.mvp.local` 不含模型 API Key，但有基础设施密码、内部凭据、AI 加密主密钥，应私下保管。已有 MySQL 卷不会重新运行首次账号脚本，改环境文件也不自动更改已有账号密码。

管理员 bootstrap **只能操作空业务库**。以下 `read -r -s` 交互输入密码，不会回显密码；输入结束按 Enter。不要将真实密码直接写入命令参数、脚本或录屏。

```sh
export LEXFLOW_TENANT_NAME='演示律所'
export LEXFLOW_ADMIN_USERNAME='admin'
printf '管理员初始密码（至少12字符，最多72个UTF-8字节）：'
read -r -s LEXFLOW_ADMIN_PASSWORD
printf '\n'
export LEXFLOW_ADMIN_PASSWORD
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml run --rm --no-deps \
  -e LEXFLOW_TENANT_NAME -e LEXFLOW_ADMIN_USERNAME -e LEXFLOW_ADMIN_PASSWORD \
  api --spring.profiles.active=bootstrap
```

等待明确日志“首次初始化完成，律所 ID=…”，记下律所 ID，再 Ctrl+C 停止初始化容器；进程保持在线不是未完成，也不能只以启动完成判断初始化成功。重复 bootstrap 会拒绝已有业务数据，不会重设管理员密码。

```sh
unset LEXFLOW_ADMIN_PASSWORD
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml up -d --wait
curl --fail http://127.0.0.1:8088/api/health
```

浏览器用律所 ID、账号、密码登录 `http://127.0.0.1:8088`。文档中 `8089` 是留下的特定验收实例，不能作为默认安装端口。`/healthz` 只证明 Web，`/api/health` 只证明 Java，内部 AI 健康不证明供应商可用。应实际创建案件、上传 TXT、主动点击“提取文字”、在“任务记录”查看原文，再保存人工文书、提交并下载 TXT 核对。

开启向量服务：先配置独立 Embedding 和供应商精确域名白名单，再：

```sh
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml --profile vector up -d --wait
```

修改 `LEXFLOW_AI_ALLOWED_HOSTS` 后需重新创建 ai-service 容器。普通文件解析和 TXT 导出不需要模型、Milvus 或模型费用。

运行：

```sh
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml ps
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml logs --tail 100 api ai-service web
docker compose --env-file .env.mvp.local -f docker-compose.mvp.yml down
```

普通 `down` 保留具名数据卷；不要在教程里让初学者追加 `-v`。升级前备份配置与数据，保持 AI 主密钥；Java 通过 Flyway 执行新增迁移，不能改已执行迁移。对外部署需已有 HTTPS 反代与 `COOKIE_SECURE=true`，项目不自动办域名证书。

## 功能、权限和输入限制

- 三角色：TENANT_ADMIN、LAWYER、READER。律师具备业务操作权限但仍须案件成员；只读不能写案件/文件。当前部分只读用户仍能看见成员管理按钮，后端返回 403；不要把可见按钮当作有效权限。
- 案件文件上传：TXT、DOCX、PDF、PNG、JPEG，单文件最多 50 MB。文字提取：主动点击“提取文字”，仅 TXT、DOCX、有文字层 PDF；PDF 最多 500 页、提取正文最多 100 万字符；当前无 OCR。律所公共资料上传仅支持可提取文字的 TXT、DOCX、含文字层 PDF。
- 人工保存/恢复/发布：用读取时并发版本和当前正文 ID；冲突 409，不覆盖已保存版本。恢复是复制历史为新版本；发布当前正文，不另追加正文。
- AI 草稿复核：版本历史中的“通过”调用 `reviewVersion(APPROVED)`，该操作立即把该 AI 版本设为当前正文；切换到不同正文时文书回到 `DRAFT`。没有额外的“采用”或“切换当前”按钮；通过不等于发布。“驳回”不采用该版本。
- AI 起草：当前已保存源正文最多 3 万字；要求 2000 字；输出最多 3 万字、10 项待补；最多 6000 token/60 秒，无 SDK 自动重试。结果私有给创建者或管理员，同时必须仍有案件/文书权限。
- AI 起草权限：有效账号及律所成员、未归档案件可编辑，`ai:generate`、`document:write/read`、`task:read`；取消另需 `task:cancel`。
- 合同：从当前案件 `AVAILABLE` 状态的 TXT/DOCX/PDF 文件行点击“审查合同”，不要求已有独立解析任务；建议先主动提取文字以核对原文。首次提交是阅读费用说明后点击“提交审查”，没有单独费用勾选框。正文最多 4 万 UTF-16 字符，最多提取 20 条，通常两次模型调用，高风险最多三次；每次最多 1800 输出 token/60 秒。精确引用真实原文。
- 合同补材：当前案件最近 100 项符合条件候选；每次 1–5 份、要求最多 1000 字、最多续审 10 轮、累计材料最多 4 万字。仅 WAITING_HUMAN/REVIEW 可补，不确定调用不能补材重发。
- 案件分析：同案件 1–10 份解析成功且有页段的可读文件；单份和合计最多 4 万字；背景最多 3000 字、要求 2000 字。归档后不能计算；报告只给创建者或管理员并重验权限。
- 知识库准备：首次填名称“创建案件知识库”，选择“已完成文字提取的文件”，点击“准备入库”；准备切片不调用模型，也不等于完成索引。然后主动“开始索引/重建索引”。
- 知识库：公共仅同律所 `knowledge:read`，不跨律所；管理员创建公共库，案件材料不会自动进库。问答要求 `knowledge:read` 和 `ai:query`，公共问答不要求特定案件权限；会话只有创建者能读。
- 问答：首轮最多 5 段；只在空结果/有效证据不足时扩大一次；每组最多 50 候选，合并去重最多 50，第二轮最多 10 段；每问题最多两次 LLM；错误/超时/引用无效不作为扩大的理由。仍不足明确拒答。
- 导出：固定提交时已保存版本，TXT 单次最多 8 MB；已批准 AI 正文才可导出。Java 自己处理，不依赖 NestJS/Milvus/模型。需当前案件读取范围及 `document:read/task:read`；取消另需 task:cancel。
- 默认 `EXPORT_RETENTION_DAYS=0` 表示没有到期日；`CLEANUP_COMPACT_AFTER_DAYS=0` 表示不压缩。配置改变不追溯旧任务。到期只影响导出对象下载，文书正文和历史不删。

## AI 费用与配置必须讲清

- 当前真实入口是侧栏“AI 配置”，不是另外寻找一个“设置”页面。
- LLM（对话）、Embedding（向量）、Rerank（排序）分别配置，不能拿对话模型当向量模型，也不会把某个 Key 自动借给别的用途。
- `LEXFLOW_AI_MASTER_KEY` 是 Base64 的随机 32 字节加密主密钥，不是模型 Key；部署者保管，一旦丢失/替换旧 Key 无法解密。未配置时普通业务可用但 AI 凭据保存不可用。
- 模型 API Key 由律所管理员页面输入，服务端加密按律所保存；普通成员不填、不能读 Key；回读只给脱敏配置，不回显 Key/密文；替换需重新输入 Key。
- 保存、查看、刷新、读任务/历史、下载不会发起模型调用。
- 连接测试、索引、主动提问、审查、分析、生成均需用户通过对应入口主动发起，并留意费用提示；具体交互不同。连接测试、AI 起草、案件分析等有费用勾选；首次合同审查是在费用提示下点击“提交审查”，没有独立费用勾选。合同补材续审有新的费用勾选；改变生成要求须重新勾选。恢复付费类型确认只授权尚未执行步骤，不覆盖恢复资格拒绝。
- 连接测试用合成文本，LLM 最多 32 输出 token，三用途最多 15 秒；每租户每用途同时 1 项，每分钟最多 3 个新请求。超时不表示没扣费，先查结果再决定是否新建。
- 地址必须 HTTPS，无账号/查询/片段；精确主机域名在部署者白名单；禁止重定向和 SDK 自动重试。
- 文档最小 DeepSeek 示例：provider DeepSeek、baseUrl `https://api.deepseek.com`、model `deepseek-flash`，域名 `api.deepseek.com`。这是仓库描述，视频若教“当前推荐型号”须以真实官方目录复核；更稳妥说“填写供应商当前可用且兼容的模型名称”。
- 接口测试成功只说明兼容，不说明法律分析正确；AI 必须核对原文、材料、法律依据、待补事项后人工决定。系统不提供供应商账户充值或统一账单。

## 任务恢复要避免误导

- 覆盖文件解析、知识索引、合同、AI 文书生成、案件分析。基础设施瞬时故障最多 10/60/300 秒三次延迟重试，再进 DLQ；任务列表中的业务“重试/恢复次数”与投递次数不同；任务行“处理记录”可查看延迟重投次数、人工恢复次数、故障与死信登记。
- 模型操作先记 STARTED，成功结果先持久化；后续存储/checkpoint/回调故障重投复用结果，不自动再次请求供应商。
- 遗留 STARTED 或结果不确定，进入 UNCERTAIN/人工处理，不能点确认或恢复绕过；应核对既有调用与材料，取消后用户主动决定是否另建付费任务。
- 已记录模型 FAILED 也不会通过投递恢复重新调用。付费步骤中的供应商 429/5xx 不能当普通瞬时网络错误重收费。
- 统一人工恢复要求当前死信、任务、版本一致，操作者及原创建者仍有权限，固定材料和模型配置 revision 有效，工作流只读探针 SAFE；付费类型再确认费用。管理员不能绕过创建者撤权。
- BUSY 禁止并发恢复；UNCERTAIN/FAILED 禁重放；INPUT_CHANGED 拒绝；UNAVAILABLE 无法验证时拒绝。勾选费用不能覆盖拒绝条件。
- 取消立即阻止结果发布，不能保证终止已经发给供应商的远程请求；迟到结果不发布。
- 合同与分析 DELIVERY 人工等待只能走统一投递恢复入口，普通复核确认和补材不适用。
- AI 起草旧 `/generation/recover` 只用于排队/执行中的同次继续，不能替代统一死信恢复。
- 工作流 AI 库必须独立初始化，普通 NestJS 启动不自动建库建表，也不自动读取项目根 .env；单机部署已由 workflow-setup 完成。Java 与 AI 服务应一起升级。

## 真实菜单、按钮与文书入口

- 侧栏依次为：工作台、案件、成员与权限、文书、任务记录、律所知识库、AI 助手、AI 配置。
- 案件列表按钮“立案新建”，弹窗标题“立案新建案件”，提交“确认立案”。必填案件编号、案件标题、业务类别；立案日期和案情简介按需填写。创建后自动成为主办律师。
- 案件详情页签：案件分析、基本信息与状态、办案人员分配、文件与证据管理、证据目录、案件文书、案件知识库。
- “基本信息与状态”可维护立案日期、案件标题、案情简介及诉求、案卷流转状态，保存按钮“保存变更”；案件编号、业务类别只读。不存在可编辑的独立“案由”“审级”字段。归档案件内容只读，可按权限“恢复办理”。
- 真正文书编辑在案件详情“案件文书”：新建文书、创建文书、编辑、保存新版本、AI 起草、导出 TXT、发布；历史中查看正文、恢复此版本、AI 草稿通过/驳回。
- 侧栏“文书”打开的是跨案件文件与审计页，页签“案件文件与证据”“操作审计日志”，不是案件文书编辑器。
- 机构账号入口是侧栏“成员与权限”，创建“添加律所成员”，调整“编辑权限”。机构角色与案件 OWNER/EDITOR/READER 是两层授权。
- 合同人工复核：填写复核意见，勾选核对声明，点击“确认已复核”；不是再次发起模型计算。

## 视频代码段复核

- 镜头 54–57 的默认新安装顺序完整：生成 `.env.mvp.local` → Compose 校验 → 构建 api/ai-service/web → 等基础设施健康 → workflow-setup → 空业务库 bootstrap → 明确完成日志、记录律所 ID、按 Ctrl+C 结束 bootstrap → unset 密码 → 正常 up → API 健康 → 浏览器业务检查。

- 视频中 bootstrap 停止方式应在画面显示 Ctrl+C；不得在初始化仍执行时中断，也不得直接跳过停止就输入下一条命令。完整带密码提示与换行的可复制命令见本文安装章节。
